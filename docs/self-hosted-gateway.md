# 自建服務部署規格

本規格定義 Control 與 SSH Gateway 的部署拓撲及隔離要求。部署程式與腳本尚未實作。

## 部署拓撲

| 拓撲 | 服務配置 | 資料隔離 |
| --- | --- | --- |
| 同主機 | Control 與 Gateway 分別作為獨立服務執行 | 各自管理資料，不共用資料庫或資料目錄 |
| 跨主機 | Control 與 Gateway 分別部署，透過服務介面通訊 | 控制資料保存在 Control，Gateway 僅保存必要執行資料 |

Control 負責帳號、裝置、節點及授權管理，Gateway 負責 SSH 通道與遊戲流量。部署拓撲不改變兩者的職責；遊戲流量不經 Control。

客戶端的自部署節點加速模式連接 SSH Gateway。接入流程及其他模式見[系統架構](architecture.md)。

## 配置與服務要求

- 部署配置分別定義 Control 與 Gateway 的服務入口、資料位置及管理方式。
- 範例使用明確佔位值；端點、金鑰及憑證由部署者提供，不包含公共節點或預設可用秘密。
- Gateway 開放服務前須完成身分驗證、主機驗證與目的地限制，不允許匿名開放代理。
- 目的地限制涵蓋名稱解析後的位址，拒絕內網、loopback、link-local 與雲端 metadata 等非允許目的地。
- Gateway 不接收本機 CA 私鑰或遊戲登入憑證，動態 TLS 維持端到端連線。

## 部署交付要求

部署指引與腳本模板須明確列出支援環境、依賴、安裝及移除流程，並記錄各服務的連線限制、逾時、金鑰輪換、日誌配置與故障排查方式。具體服務端作業系統、連接埠與管理命令尚未定義。

部署者負責主機更新、存取控制及資料管理；相關資料處理要求見[資料處理與隱私](privacy.md)。

## 驗收條件

驗收包含服務配置檢查、隔離環境連線測試及部署環境驗證，分別記錄結果：

- Control 與 Gateway 可獨立管理，資料路徑及儲存存取符合隔離要求。
- 未通過身分驗證的連線及非允許目的地遭拒絕。
- 遊戲流量只經 Gateway，動態 TLS 內容不被服務端解密。
- 範例與交付包不包含真實部署秘密，診斷紀錄符合安全政策。
