# 系統架構

本規格定義元件職責、流量路徑與技術約束。實作狀態見[文件索引](README.md)。

現階段的應用適配範圍暫限於 Granblue Fantasy（GBF），PAC 分流與靜態資源白名單依此範圍定義。

## 客戶端與元件分工

客戶端以 macOS arm64 與 Windows x64 為目標平台，使用 Tauri 2、React 與 Rust；服務端規劃使用 Go、SQLite、Bubble Tea TUI 與獨立 SSH Gateway。0.3.0 實作桌面客戶端，Control 與 Gateway 尚未實作。

| 元件 | 職責 |
| --- | --- |
| 桌面客戶端 | 提供設定介面，管理本機代理、上游連線與靜態快取 |
| 瀏覽器代理插件 | 執行 PAC 規則，將指定流量導向本機代理 |
| Control | 管理專案帳號、裝置、節點與授權，保存控制資料 |
| 管理 TUI | 以 Bubble Tea 提供服務端管理介面 |
| SSH Gateway | 驗證連線身分、限制目的地並轉發遊戲流量 |

Control 的帳號與裝置識別屬於本工具的授權體系，不包含遊戲帳號或登入憑證。

## PAC 分流與上游模式

PAC 決定瀏覽器請求是否進入本機代理；未導向本機代理的請求依 PAC 規則連線。進入本機代理的請求依所選模式使用下列路徑。

| 模式 | 流量路徑 |
| --- | --- |
| 直連 | 瀏覽器 → 本機代理 → 原始服務 |
| 上游代理 | 瀏覽器 → 本機代理 → HTTP／SOCKS5 代理 → 原始服務 |
| 自部署節點加速 | 規劃路徑：瀏覽器 → 本機代理 → 自建 SSH Gateway → 原始服務；0.3.0 停用 |

各模式遵循相同的靜態快取與動態轉發約束。0.3.0 僅接受直連及上游代理模式；本機代理預設監聽 `127.0.0.1:8123`，PAC 位於 `/proxy.pac`。直連指本機代理直接連接上游，符合條件的靜態請求仍可使用本機快取。

## 靜態資源快取

快取僅接受符合靜態來源、路徑白名單及快取條件的資源。無法確認資格的內容不寫入快取；動態遊戲流量不進入快取流程。

快取保存原始素材內容，遵守適用的 `Cache-Control`、條件重新驗證及失效語意，並提供容量限制與清除機制。快取內容不隨倉庫或安裝套件散布。

靜態 HTTPS 快取採本機 CA 方式，須由使用者明確安裝及信任 CA。本機代理終止允許範圍內靜態來源的 TLS，再建立並驗證上游 TLS。代理規則須將動態遊戲與登入來源排除於 TLS 終止流程之外；CA 私鑰僅保存在本機。靜態主機限於 `prd-game-a-granbluefantasy.akamaized.net` 與 `prd-game-a-granbluefantasy-steam.akamaized.net`；只快取 `/assets/`、`/assets_en/` 路徑下符合副檔名與 HTTP 快取條件的內容。

磁碟預設 5 GiB；RAM 上限 2048 項／128 MiB；單物件上限 16 MiB。快取使用 SQLite 索引、SHA-256 驗證與 LRU，有界背景寫入在正常停止前排空，清理或替換會使排隊的舊寫入失效。素材預取只解析可快取的靜態 JS／JSON 引用；記憶體預熱只讀取有效磁碟內容；體檢在停止代理後檢查及修復資料。背景工作採有界佇列並讓出前台流量，詳細限制見[快取規格](cache.md)。

## 動態 TLS 通道

動態 HTTPS 流量透過 CONNECT 等通道，以不透明位元組串流轉發。直連及上游代理均維持瀏覽器與原始服務之間的端到端 TLS。

轉發層不解密、不修改、不快取、不重播動態請求或回應，不解析遊戲內容、不保存遊戲 Cookie 或登入憑證，也不代替使用者呼叫遊戲 API。通道中斷後不自動重新發送遊戲請求。

## 控制平面與流量平面（規劃）

| 平面 | 服務 | 資料與流量邊界 |
| --- | --- | --- |
| 控制平面 | Control | 保存帳號、裝置、節點及授權資料；不承載遊戲流量 |
| 流量平面 | SSH Gateway | 保存必要執行資料並承載轉發連線；不直接存取 Control 資料庫 |

Control 與 Gateway 透過明確的服務介面交換必要的授權及節點資訊。介面協定與資料格式尚未定義。

同主機與跨主機部署均維持獨立服務與資料，不直接共用資料庫或資料目錄。Gateway 不接收本機 CA 私鑰或遊戲憑證；可觀察的連線資訊見[資料處理與隱私](privacy.md)。

## 部署邊界

遠端服務由部署者自行配置及維護。專案提供部署規格，部署交付範圍為自建指引與腳本模板；配置不附公共節點、真實端點或預設可用憑證。服務隔離與部署驗收見[自建服務部署規格](self-hosted-gateway.md)。

## 設定與執行狀態

設定使用 `config.json`，`schemaVersion` 為 `1`，包含 `settings`。模式、代理端點、監聽埠、HTTPS 快取、容量、登入啟動及語言／主題持久保存；`settings.cachePreferences` 保存 `prefetchEnabled` 與 `warmupEnabled`，兩者預設開啟，缺少欄位時套用預設；密碼不寫入 JSON。停止後重啟重設本次統計；運行中切換保留計數及時長。

## 驗收條件

- PAC 分流結果與三種模式的實際上游路徑一致。
- 動態流量不進入 CA 或快取處理；轉發位元組保持不變，斷線後不重播請求。
- 靜態快取遵守白名單、完整性、重新驗證與失效條件；預取不執行腳本、不攜帶認證，預熱不回源或污染使用統計。
- 體檢具備取消、修復統計與檔案邊界保護，與代理啟動及清理互斥。
- Gateway 身分驗證及目的地限制有效，遊戲流量不經 Control。
- 同主機部署具備獨立服務與資料；macOS／Windows 分別具備建置與裝置驗證紀錄。
